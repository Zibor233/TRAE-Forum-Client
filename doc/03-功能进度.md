## 登录与授权

| 项 | 内容 |
| --- | --- |
| 实现要点 | RSA 2048 / PKCS#1 v1.5 生成密钥对 → 打开官方授权页 → 手动粘贴 Base64 payload → 解密校验 nonce → `User-Api-Key` 请求头 + `/session/current.json` 取用户名并落库 |

## 限流与「无感」优化

| 项 | 内容 |
| --- | --- |
| 代理分桶 | 主体读 30/s（突发 100）；`/t/{id}.json`、`/notifications.json` 各 20/s（突发 60）；`/chat/*` 10/s（突发 30）；写 20 次/分钟 |
| 本机排队 | 命中限流先在代理内部排队，最多 5 秒，超时才返回 429 |
| 前端队列 | `src/lib/requestQueue.ts`：全局并发 **4**，三级优先级 `user > normal > prefetch`，prefetch 最多占 3 槽（始终给 user 留 1 槽），同 URL 300ms 合并 |
| 静默重试 | 读失败静默重试 3 次（300ms → 1s → 2.5s + 抖动）；429 按 `retry-after` 退避；连续 3 次失败才暴露「重新加载」 |
| 缓存优先 | `src/lib/cache.ts`（`trae-lite.cache.v2.*`）：信息流 10 分钟、通知 5 分钟、资料 15 分钟、聊天概览 5 分钟；401/403 不写缓存，内容无差异不重渲染 |
| 预取 | 首屏后 `top.json?period=weekly` + `categories.json`（prefetch 优先级）；hover 100ms 预取详情，每屏最多 3 个；Tab 切换预热；距底 1.5 屏下一页 |
| 文案 | 界面不出现「请求有点多」「稍后重试」「rate_limited」「状态码 X」；空态为「暂无内容，点击刷新」 |
| 验证方式（真实 key 全场景） | 98 次请求、峰值并发 **4**、本机 429 **0**、论坛 429 **0**、缓存命中 **54**、冷首卡 **61ms** / 暖首卡 **46ms**、CLS **0.002**、UI 错误提示 0 次 |
