# 02 · 接口与后端结论

更新时间：2026-11-05
一句话摘要：以下为 `forum.trae.cn`（Discourse）在本项目中实际调用/探测过的接口与结论，状态码均为实测值；未实测的条目单独标注。

## 鉴权与登录

### User API Key 授权流程（实测）

| 探测 | 结果 |
| --- | --- |
| `GET /user-api-key/new?...&auth_redirect=http://localhost:5173/...` | 200 text/html，页面内 `"user_api_key_authorization":"{\"state\":\"generic_error\"}"` |
| `GET /user-api-key/new.json`（不带 `auth_redirect`） | 302 → SSO 登录页（说明参数校验本身通过） |
| `GET /user-api-key/new`（不带参数） | 400 |
| `GET /user-api-key/not-a-real-route` | 404（路由存在性对照） |
| `HEAD /user-api-key/new` | 200，响应头 `X-Discourse-Route: user_api_keys/new`、`Auth-Api-Version: 4`、`Auth-Api-Device-Code: true` |
| `GET /session/csrf.json` | 200 |

**结论**：User API Key 流程本身开启，但站点的 `allowed_user_api_auth_redirects` 未包含任何本机回调（试过 `localhost:5173`、`127.0.0.1:5173`、`:3000`、`:8080`、`https://`、`example.com`、`forum.trae.cn/user-api-key/callback`，全部 `generic_error`）。因此只能走官方默认兜底：授权页展示 Base64 payload → 用户复制回本应用 → 前端解密。

### 密钥细节（`src/lib/auth.ts`）

| 项 | 结论 |
| --- | --- |
| 密钥算法 | RSA 2048，**PKCS#1 v1.5**（与 Discourse 默认 padding 一致），由 `jsencrypt` 生成 |
| payload | Base64，解密后含 `key`、`nonce`、`push`、`api: 4` |
| nonce 校验 | 解密结果与生成时保存的 nonce 比对，不一致直接拒绝 |
| 用户名来源 | payload 不含 username，登录后用 `GET /session/current.json`（带 `User-Api-Key`）读取 `current_user.username/name/avatar_template` |
| 登录态存储 | `localStorage`：key、username、client_id、nonce、scopes、createdAt（key `trae-lite.user-api-key.v1`） |
| scopes | `read,write,message_bus,session_info` |
| 请求头 | `User-Api-Key`（代理同时放行 `Api-Key` / `Api-Username`） |
| CSRF | API Key 鉴权的写操作免 CSRF，前端不发 `X-CSRF-Token` |

## 只读接口

| 路径 | 方法 | 鉴权 | 返回要点 | 实测状态码 |
| --- | --- | --- | --- | --- |

| `/latest.json?category={id}&page=N&order=default&tags[]=x` | GET | 匿名 | 分类筛选 + 标签筛 + 排序；`order=likes` 为按赞数 | 200 |
| `/top.json?page=N` | GET | 匿名 | 热门列表，含 `views`、`like_count` | 200 |
| `/top.json?period=weekly` | GET | 匿名 | 周热门（首页预取使用） | 200 |
| `/top.json?period=all` | GET | 匿名 | 站点不可用 → 前端退回按赞数排序（`order=likes`） | 实测不可用 |
| `/categories.json` | GET | 匿名 | `category_list.categories[]`：`id/name/color/topic_count/parent_category_id/read_restricted` | 200 |
| `/c/{slug}/{id}.json` | GET | 匿名 | 分类页信息流（前端主要用 `latest.json?category=` 形式） | 未实测（仅代码兼容） |
| `/t/{id}.json?page=N` | GET | 匿名/带 key | `title/posts_count/like_count/views/tags/image_url`；`post_stream.posts[]` 每页 20 楼 | 200 |
| `/t/{topicId}/posts.json?post_ids[]=...` | GET | 匿名 | 按楼层 id 批量取楼层（通知摘要用），走代理 60s 缓存 | 200 |
| `/search.json?q=xxx` | GET | 匿名 | `topics[]`、`posts[]`（`blurb`）、`grouped_search_result` | 200 |
| `/tags.json` | GET | 匿名 | `tags[]`（名称、计数），编辑器标签建议用 | 200 |
| `/tag/featured.json` | GET | 匿名 | 社区置顶（`tag=featured` 的 topic 列表） | 200 |
| `/emojis.json` | GET | 匿名 | **实际是「分组名 → 表情数组」的对象**（如 `{"smileys_&_emotion":[...]}`），非标准 `{ emojis: [...] }`；前端两种都兼容 | 200 |
| `/u/{username}.json` | GET | 需 key | 资料：`username/post_count/avatar_template` 等；匿名访问被隐藏 | 200（带 key） |
| `/u/{username}/bookmarks.json` | GET | 需 key | 收藏列表（仅本人可见） | 200 |
| `/user_actions.json?username=&filter=&offset=` | GET | 需 key | 点赞/回复等动作列表（`filter=1` 点赞） | 200 |
| `/topics/created-by/{username}.json?page=N` | GET | 需 key | 用户创建的话题 | 200 |
| `/session/current.json` | GET | 需 key | 校验 key、取用户名；代理对该路径不缓存 | 200 |

## 写接口

| 路径 | 方法 | 鉴权 | 请求体 / 参数 | 实测状态码 |
| --- | --- | --- | --- | --- |
| `/post_actions.json` | POST | 需 key | `{ id: postId, post_action_type_id: 2, flag_topic: false }` | 200 |
| `/post_actions/{id}?post_action_type_id=2` | DELETE | 需 key | 无 body（取消赞） | 200 |
| `/posts.json` | POST | 需 key | 回复：`{ raw, topic_id, reply_to_post_number? }`；发帖：`{ raw, title, category, tags[]? }` | 200；受限分类 403 |
| `/uploads.json` | POST | 需 key | `multipart/form-data` 图片 | 200（实测 781ms） |
| `/chat/{channelId}` | POST | 需 key | `{ message }` → `{ success, message_id }`（Discourse Chat 真实写路由） | 200（实测发送成功） |
| `/chat/api/channels/{id}/messages` | POST | 需 key | 文档式路径 | 404（不可用） |
| `/chat/api/direct-message-channels` | GET | 需 key | 私信频道专用路径 | 404（不可用，改走 `/chat/api/me/channels`） |

写失败时前端直接展示论坛返回的 `errors` 原文（例如受限分类返回「您没有权限查看请求的资源。」）。

## 通知

| 项 | 实测结论 |
| --- | --- |
| 路径 | `/notifications.json?limit=40&offset=N`（需 `User-Api-Key`，代理不缓存） |
| 分页参数 | **`offset` 生效；`page` 无效** |
| 每页条数 | `limit=40` 有效 |
| 实测分页 | `offset 0/40/80/120` 各返回 40 条；`offset 160` 返回 2 条 |
| 总数 | `total_rows_notifications` = 162（发测试帖后曾为 163） |
| 到底判定 | `load_more_notifications` 到底后**仍返回 URL 字符串**，不能作为结束依据；需结合页长（<40）与 `fetched >= total` 判定 |
| 字段要点 | `notifications[]` 含 `id/notification_type/read/topic_id/post_number/created_at/data{topic_title,excerpt,display_username,username1,original_post_id,post_number,group_name}` |

### 通知类型映射（`src/pages/NotificationsPage.tsx`）

| type | 含义 | 前端处理 |
| --- | --- | --- |
| 1 | 在帖子里提到了你 | 铃铛图标 |
| 2 | 回复了你的帖子 | 回箭头图标 |
| 3 | 引用了你的回复 | 回箭头图标 |
| 5 / 25 | 赞了你的帖子（赞 / 表情回应） | 爱心图标，参与「同楼层合并」 |
| 6 | 别人给你发私信 | 信封图标，`ACTION_LABELS` 显示「发来一条私信」 |
| 7 | 邀请你加入私信 | 信封图标 |
| 16 | 群组收件箱（群组动态） | 发起人取 `data.group_name`，不取 `data.username`（后者是接收人自己） |

### 「帖子 vs 回复」的判断

| 场景 | 规则 |
| --- | --- |
| 被赞楼层 | `data.original_post_id` 为楼层 id；`data.post_number` / 顶层 `post_number` 为楼层号 |
| 是否主题首帖 | `post_number === 1` 为主题首帖，其余一律按回复处理（`src/pages/NotificationsPage.tsx`、`src/lib/author.ts`） |
| 合并键 | `('like', type, topic_id, original_post_id ?? post_number ?? id)`，同一帖子不同楼层**不跨楼层合并** |
| 去重键 | 仅按通知 `id` 去重；不能按 `(type, topic_id, post_id)`，否则同一楼层不同人的点赞会被误删 |

## Chat（消息）

| 路径 | 方法 | 返回要点 | 实测状态码 |
| --- | --- | --- | --- |
| `/chat/api/me/channels` | GET | 已加入频道 + 私信列表（`{ channels, direct_message_channels? }`），左栏数据源 | 200 |
| `/chat/api/channels` | GET | 全部公开频道（含未加入），左栏「频道」分组 | 200 |
| `/chat/api/channels/{id}/messages?page_size=50&direction=future` | GET | 最新一页消息（首次进入） | 200 |
| `/chat/api/channels/{id}/messages?page_size=50&direction=past&target_message_id={firstId}` | GET | 向上翻页（更早消息） | 200 |
| `POST /chat/{id}` | POST | 发送消息，body `{ message }`，返回 `{ success, message_id }` | 200 |

说明：`target_message_id` 为站点实际字段；`before_message_id` 也可用（代码注释记录）。频道列表只包含已加入频道，未加入的公开频道需从 `/chat/api/channels` 读取。

## 代理相关结论（`proxy/server.mjs`）

| 项 | 值 |
| --- | --- |
| 端口 | `PROXY_PORT` 环境变量，默认 8787 |
| 上游 | `https://forum.trae.cn` |
| GET 缓存 | 60 秒内存缓存，命中返回 `x-proxy-cache: HIT`；个性化接口（通知/聊天/用户资料等）不缓存 |
| 读限流 | 主体 30 次/秒、突发 100；`/t/{id}.json` 与 `/notifications.json` 各 20 次/秒、突发 60；`/chat/*` 10 次/秒、突发 30 |
| 本机排队 | 命中限流先内部排队，最多等 5 秒；仍无配额才返回 429（带 `x-proxy-rate-scope`） |
| 写限流 | 每 IP 每分钟 20 次固定窗口 |
| 写白名单 | `POST /post_actions(.json)`、`DELETE /post_actions/{id}`、`POST /posts(.json)`、`POST /uploads.json`、`POST /chat/{id}` |
| 鉴权读白名单 | `/session/current.json`、`/notifications.json`、`/chat/*`、`/u/{name}.json`、`/u/{name}/bookmarks.json`、`/user_actions.json`、`/topics/created-by/*` |
| CORS | `access-control-allow-headers` 含 `User-Api-Key / Api-Key / Api-Username` |
| 超时 | 上游 20 秒 |

## 错误归一化（`src/api.ts`、`src/lib/errors.ts`）

| 状态 | 前端文案 |
| --- | --- |
| 404 | 内容不存在或已被删除 |
| 401 / 403 | 没有权限或密钥已失效 |
| 其他（含 429） | 暂时无法加载 / 暂无内容（界面不出现「请求有点多」「稍后重试」「状态码 X」） |
| 429 | 读取 `retry-after` 头或响应体 `retryAfter`，用于静默退避；路径级冷却最长 60 秒 |
